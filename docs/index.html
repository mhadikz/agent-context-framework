Why you need it

Long chats rot. Files do not.

A fresh chat should already know the stack, the commands, the error shape, and what the team refused to adopt. You stop repeating the same constraints, and the agent stops inventing a second architecture beside the one you have.

01 — Rules

How to behave

AGENTS.md is the directive Cursor, Copilot, and Codex load from the root. CLAUDE.md and GEMINI.md are the entry points those CLIs actually look for.

02 — Sprint

What to build next

PLAN.md holds the goal and the non-goals. BACKLOG.md is the queue. SESSIONS.md is the short memory a new chat can resume from.

03 — Governance

What not to rewrite

DECISIONS.md records why the stack exists. Design, voice, API contracts, the data register, and the runbook keep later changes inside the same system.

When to use it

Pick the team size, then the stack.

Every production app needs the same foundations: boundaries, validation, authorization, tests, errors, logs, migrations, and CI. Clean Architecture, tactical DDD, CQRS, event sourcing, and microservices show up only when a real problem needs them.

Small · 1–8 engineers

One product, one deployable

Feature folders, one PostgreSQL, server-side authorization. No hexagonal ceremony and no extra service. Next.js or NestJS examples are ready to copy.

Medium · several squads

A modular monolith

Layers only inside complex domains. Vendor ports, compatible migrations, a glossary, and a runbook. Still one product, not a service per module.

Large · enterprise

Contexts with owners

A context map, versioned contracts, audit, and a written reason before any service is extracted. The company being large is not that reason.

How to use it

Copy one folder into the project root.

Blank files live in templates/. Next.js and NestJS examples are already arranged in the layout below. Copy the contents of one size folder, then fill the [...] placeholders.

  1. Step 1

    Choose a set

    Generic templates for any stack. Or examples/nextjs/<size> and examples/nestjs/<size> for small, medium, and enterprise.

  2. Step 2

    Keep three files at the root

    AGENTS.md, CLAUDE.md, and GEMINI.md stay at the root because those tools load them automatically. Everything else goes in docs/context/.

  3. Step 3

    Point the agent at the rest

    The root AGENTS.md lists the context files. The agent reads them at the start of a session, and again before architecture, API, data, or copy changes.

  4. Step 4

    Update the living files

    Refresh SESSIONS.md and BACKLOG.md at the end of a working session. Keep each root file under 300 lines.

Where each tool looks

  • Cursor, GitHub Copilot, and Codex read a root AGENTS.md.
  • Claude Code reads a root CLAUDE.md.
  • Gemini CLI reads a root GEMINI.md.
  • They do not open PLAN.md or DECISIONS.md unless AGENTS.md points at them.
  • In a monorepo, keep one set at the repository root. Add a short AGENTS.md in a package only when that package has its own commands.
The engineering rule

Foundations are mandatory. Advanced patterns are optional. The full map of what each team size takes is in ENGINEERING.md.
